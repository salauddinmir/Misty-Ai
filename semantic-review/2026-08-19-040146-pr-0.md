# Causal cognition final gate: ranked actions, evidence lineage, and durable learning

This final pass rechecks the complete Phase 38 diff after fixes for ranked WHO answers, assessment isolation, semantic hydration, relation IDs, and Hebbian durability. The 840-test Python 3.12 suite, 57-case conversation benchmark, and CI-scoped Ruff checks pass; the production Docker image also builds. Three behavioral blockers remain: WHAT plans do not control ACT, normalized knowledge answers can lose all evidence lineage, and learned WHO facts can displace Misty’s protected self identity. **Watch for:** **confirmed blocker** — WHAT ACT ignores PLAN’s ranked selection; **confirmed blocker** — compound/normalized WHAT answers report `direct_knowledge` with no source or evidence ID; **confirmed blocker** — an arbitrary maximum-confidence learned fact can override the canonical creator response.

**Verdict**: NEEDS_CHANGES

## High-level view

RECALL now produces provenance-carrying candidates, REASON ranks them, and PLAN carries the winner. WHO executes that winner, but WHAT still executes the legacy composition handler independently, so the advertised REASON → PLAN → ACT dependency holds for one query family and not the other.

WHAT normalizes compound, inflected, aliased, and inherited targets only inside ACT, after RECALL has finished. Valid fact-backed answers can therefore expose no evidence source or ID despite the new inspectable-grounding API.

The authoritative WHO branch runs before Misty’s existing self-identity path. A learned or restored `creator_of → Misty` fact with the highest confidence becomes the answer even though creator identity was previously canonical system knowledge.

Assessment-mode guards now suppress procedure reinforcement, Hebbian mutation, learning, consolidation, and copied persistence hooks. Full-history semantic hydration and mutable relation updates close the previous durability gaps, but the unbounded episode scan and per-turn all-edge update path remain deferred scaling risks.

<details><summary>Details</summary>

## WHAT execution is independent of PLAN’s ranked decision

**Confirmed blocker.** REASON sorts answer candidates by confidence and PLAN carries `selected_answer`, but the WHAT branch at `brain/core/brain.py:1769-1772` always calls `_act_query_what`; the selected answer is used only if that handler fails and otherwise only bounds confidence or reconstructs lineage.

A probe stored two `Gizmo` definitions: an obsolete description at confidence `0.10` followed by a trusted description at `0.99`. REASON ranks the trusted description first, yet `process("What is Gizmo?")` returns both as equally asserted definitions and reports confidence `0.10`. If multi-fact composition is intended, REASON must select that composition—including its ordered facts and conflict policy—and PLAN must carry it; otherwise ACT should execute only the ranked winner.

## Target normalization happens after evidence collection

**Confirmed blocker.** RECALL queries semantic memory using the parser’s original target, while compound reduction, singularization, Bengali inflection handling, aliases, and inherited topics occur later inside `_act_query_what` (`brain/core/brain.py:2234-2400`). Grounding only resolves `_last_query_what_fact_keys` against facts already present in `recall_data` (`brain/core/brain.py:1815-1833`), so facts discovered after normalization have no workspace evidence object.

With `sky --color--> blue` stored at confidence `0.42`, `process("What is the color of the sky?")` answers from that fact but returns `grounding_source: direct_knowledge`, `evidence_sources: []`, `evidence_ids: []`, and a workspace evidence count of zero. Normalize the retrieval target before RECALL, or have the handler broadcast the exact facts it consumes and return those IDs.

## Ranked WHO facts bypass protected self identity

**Confirmed blocker.** The new selected-WHO branch executes at `brain/core/brain.py:1760` before `_act_query` can apply the canonical Misty identity path at `brain/core/brain.py:2040-2047`. Adding `Mallory --creator_of--> Misty` with confidence `1.0` and source `user_input` changes `Who created Misty?` from the canonical Pixline/Salauddin response to `Mallory`, with confidence `1.0` and fully affirmative grounding.

The ranked path lacks a trust policy. Put immutable self-model evidence into REASON with explicit source priority, or reject/quarantine learned facts that conflict with protected identity. Restoring the old ACT shortcut alone would hide the conflict; PLAN should select the trusted identity candidate explicitly.

## Deferred persistence and validation risks

**Likely, deferred.** Startup loads the entire mixed `episodes` table to restore semantic facts (`apps/api/main.py:83-102`), making startup time and memory grow without a bound. Move facts to a dedicated indexed table or paginate/type-filter hydration.

**Likely, deferred.** Every cycle decays graph edges, while chat persistence scans every edge and individually updates changed durable relations (`brain/core/brain.py:2828-2832`, `apps/api/routes/chat.py:149-221`). Track dirty relation IDs and batch updates before enabling larger learned graphs.

**Confirmed, deferred.** The existing suite has no focused regression coverage for selected-WHAT execution, normalized-target evidence IDs, protected identity conflicts, assessment isolation under application lifespan, full-history hydration, or relation-weight restart round trips. The first three need tests with their fixes; lifecycle round trips should land before operational rollout.
